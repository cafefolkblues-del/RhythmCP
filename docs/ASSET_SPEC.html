에셋 명세서

리듬 파트(M1)에 들어갈 캐릭터·노트·이펙트·UI·효과음의 규격. 기준은 640×360 픽셀 격자와 컬러 원본(흑백은 게임 안에서 처리)이다. 확정 = 합의된 규칙 · 제안 = 아트 작업 보고 조정 가능한 수치 · TODO = 나중에 정할 것.

1

공통 규격

여기가 바뀌면 모든 에셋과 레이아웃이 다시 작업된다. 가장 먼저 지켜야 할 규칙.

기준 해상도
640 × 360 확정정수배 확대: ×2 = 720p, ×3 = 1080p, ×6 = 4K. 픽셀 크기가 들쭉날쭉해지지 않는다.
화면 비율
16:9 고정 확정UI는 해상도에 고정하지 않고 앵커로 배치.
월드 단위
1유닛 = 32px (Pixels Per Unit 32) 확정화면 폭 20유닛 × 32 = 640px. 지금까지 배치한 월드 좌표가 그대로 맞는다.
색
전부 컬러로 제작 확정흑백은 렌더링 단계에서 처리하고, 클라이맥스 무미스 때 원본 색이 픽셀 단위로 번져 나온다(M6). 흑백으로 그리면 번질 색이 없다.
흑백 구분
색이 아니라 모양으로도 구분돼야 한다 확정플레이 대부분이 흑백 화면이라 색만 다른 에셋(동시치기·보너스 노트 등)은 구분이 사라진다.
UI 기준
UI Canvas도 640 × 360 기준 확정UI 픽셀 아트를 1배로 올리고 정수배로 확대. 현재 1920×1080 기준 레이아웃은 코드 쪽에서 재조정한다(§11).
폰트
Galmuri11 (OFL) · 글자 크기는 11px의 배수 권장 확정원래 설계 크기의 배수에서 픽셀이 선명하게 찍힌다.
임포트 설정
필터 Point · 압축 없음 · 밉맵 끔 확정픽셀이 번지지 않게.
2

제작 흐름

프로토타입은 임시 AI 일러로 채운다(M1 스펙 §11). AI 일러는 픽셀 격자에 맞지 않으므로 반드시 픽셀화 단계를 거친다.

1. 원본AI 임시 일러 (컬러, 큰 해상도)
→
2. 픽셀화 스크립트규격 크기로 축소 · 격자 정렬
→
3. 규격 PNG§9 파일 규칙대로 이름
→
4. 투입폴더에 넣으면 임포트 설정 자동
→
5. 교체스프라이트 칸에 끼우기
픽셀화
레포 안 스크립트로 처리 확정 TODO 제작입력: 원본 이미지 + 목표 크기. 처리: 가장 가까운 픽셀로 축소(보간 없음), 반투명 가장자리 정리(알파 임계값), 선택적으로 팔레트 색 수 제한. 출력: §9 이름 규칙의 PNG.
최종 아트
아트팀 합류 후 같은 규격으로 교체 확정스프라이트 칸만 바꾸면 되도록 코드가 준비되어 있어야 한다(§11).
3

캐릭터 반응 스프라이트

판정선 왼쪽에서 노트를 받아치는 플레이어블 캐릭터. 상태는 코드의 ReactionState와 1:1로 대응한다.

크기
128 × 128px 한 장 제안위아래 레인 간격(약 112px)을 덮는 크기. 캐릭터 실루엣은 이 안에서 여백 자유.
기준점
발밑 중앙 · 오른쪽을 봄 확정노트가 오른쪽에서 온다(M1 §1).
프레임
프로토타입 상태당 1장 확정 · 최종 프레임 수 TODO1장으로도 상태 구분이 되게 포즈를 확실히 다르게.

코드 쪽 반영할 것

에셋이 칸에 끼우기만 하면 되도록 준비할 작업(개발 쪽 할 일 목록).

  • 픽셀화 스크립트 제작(§2).
  • UI Canvas 기준을 640 × 360으로 바꾸고 레이아웃 재조정, 글자 크기 11px 배수로.
  • 카메라 픽셀 퍼펙트 설정(640 × 360, 32 PPU, 정수배 확대).
  • 노트 스프라이트 칸 분리: 빠른 타격·동시치기·보너스를 색 대신 스프라이트로. 홀드 몸통을 가로 반복(타일)으로.
  • 판정 글자 이미지 칸, 카운트다운 이미지 칸.
  • 이펙트 재생기: 스트립 → 12fps 재생, 풀링(⑥ juice 골격과 같이).
  • 판정별 효과음 칸(지금은 입력음 1개).
  • 흑백 렌더 + 색 번짐(M6) — 에셋이 컬러로 들어오므로 흑백 처리를 게임 쪽에서.
  • 곡별 배경 칸(SongDefinition).
